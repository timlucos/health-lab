# Промпт проекта «Здоровье Лаб»

Этот файл — постоянное задание для любой сессии, которая развивает приложение. Прочитай его целиком, затем `docs/DESIGN.md` (дизайн-код) перед любым изменением интерфейса.

## Кто и зачем

- Приложение для одного человека — владельца. Он пишет по-русски, отвечать ему только по-русски, на «вы», коротко и по делу.
- Цель владельца: мышечная масса и выносливость к 12.04.2027. Зал DDX Fitness, принимает креатин моногидрат.
- Часы: Fitbit Air, данные идут через Google Health API v4.
- Измеряет только вес. Рост и возраст указаны в профиле («Цель»). Обхваты, процент жира и прочие замеры не просить и не показывать (решение 13.10.2026).
- Пользуется с iPhone как PWA с экрана «Домой». Уведомления приходят через Web Push.

## Что делает приложение

| Раздел | Что есть |
|---|---|
| Сегодня | Готовность, кольца, сон, плитки показателей, заряд часов, уведомления, совет тренера на день |
| Сон, Нагрузка, Данные | Тренды, нормы, таблица по дням, CSV, отчёт для врача (`/report`) |
| Тренер | План и запись тренировки (упражнения по-русски, с анимацией), разминка, история, прогресс веса с прогнозом к цели, разборы ИИ, чат |
| Питание | Кольца КБЖУ; запись еды по фото, штрихкоду, этикетке, тексту и из недавнего; вода и напитки; база рецептов с подбором по продуктам дома и фото холодильника; режим готовки по шагам с картинками и таймером; недельный рацион из базы рецептов (без ИИ) с покупками; быстрые блюда кофейни Дринкит; разбор привычек питания |
| Уведомления | Утренняя сводка (время настраивается), вечерняя проверка, итоги недели по воскресеньям, «поставьте часы на зарядку» при заряде 20% и ниже |

## Устройство

- **Фронтенд.**
  - Next.js 16 и React 19, все экраны клиентские, графики на своём SVG. Репозиторий `timlucos/health-lab`, ветка `main`.
  - Каждый пуш в `main` выкладывается на Vercel: https://health-lab-one.vercel.app. Проверить выкладку: `gh api repos/timlucos/health-lab/commits/main/status`.
- **Данные.**
  - Supabase `yfdaldpzbfyzoancmywn`. Схема `health` наружу закрыта.
  - Клиент работает только через функции `public.hl_*` (SECURITY DEFINER, `search_path = ''`). Каждая начинается с `if not health.is_owner() then raise … '42501'`.
  - Владелец определяется по id учётной записи и почте сразу (`sync_state.owner_uid` и `owner_email`).
- **Серверные функции** (`supabase/functions`):
  - `coach-ai`: весь ИИ. Типы запросов: workout, weekly, daily, health, chat, food, label, barcode, fridge, nutrition, mealplan.
  - `morning`: уведомления.
  - `devices`: заряд часов.
  - `google-health`: сбор данных, лежит в `/mnt/project-files/fitbit-app/health-lab/supabase`, не в репозитории.
- **Расписание** (pg_cron):
  - `health-push-tick` раз в 5 минут вызывает `health.push_tick()`, та решает, какое уведомление пора слать;
  - `health-devices` раз в час;
  - сбор данных Google Health.
- **Миграции.** Нумерованные файлы в `supabase/migrations`. Каждое изменение базы сохранять файлом с тем же текстом, что применён.

## Правила, которые нельзя нарушать

1. **Секреты.**
   - Ключи ИИ, сервисный ключ и OAuth-токены не попадают в код, в чат, в логи и в браузер.
   - Новый ключ владелец сам добавляет в секреты Supabase; в чат его не присылать.
   - Не доставать токены SQL-запросами и не печатать значения секретов.
2. **Вход только у владельца.**
   - Регистрация закрыта (`shouldCreateUser: false`).
   - Любая новая функция данных проверяет `health.is_owner()`; права выдаются только `authenticated` (и `service_role`), у `anon` и `public` отзываются.
3. **Личные данные — минимум наружу.** В ИИ уходят только нужные цифры и еда: без имени, почты и адресов. Бесплатным ИИ-сервисам данные не отправлять. Адрес MAC и серийные номера устройств не сохранять.
4. **ИИ — дёшево и прозрачно.**
   - Рутина идёт через DeepSeek (`AI_MODEL_LIGHT`, около 1 ₽ за ответ); тяжёлое (недельный разбор, здоровье, фото) — через Claude (`AI_MODEL`). Рацион на неделю собирается в браузере из базы рецептов (`lib/weekplan.ts`): длинные ответы ИИ обрывались и списывали деньги без результата (13.10), к ИИ-рациону не возвращаться.
   - Каждый ответ и каждая неудача с ценой записываются через `hl_ai_log` и видны во «Все разборы». Цена в ₽ показывается рядом с ответом.
5. **Наука, без диагнозов.** Советы опираются на метаанализы и рекомендации (ВОЗ, ACSM, ISSN, AASM). Оценки ИИ помечаются как оценки. Тревожные признаки — совет обратиться к врачу.
6. **Безопасность сайта.** Заголовки защиты из `next.config.ts` не ослаблять. Камера разрешена только этому сайту. Сервис-воркер ничего не кэширует.

## Как работать

- **Дизайн.** Сначала `docs/DESIGN.md`: компоненты `Header`, `Card` с цветом раздела, `.btn`, `.chip`, `.note`, токены цветов из `globals.css`. Новых стилей без нужды не заводить; всё по-русски, без жаргона. Проверять в тёмной и светлой теме на ширине iPhone (390 px).
- **Проверка перед выкладкой.**
  - `npx tsc --noEmit` и `npm run build`.
  - Скриншоты Playwright с подменой ответов `rpc` (Chromium в `/opt/pw-browsers/chromium`, сервер `next start -p 3123`).
  - Серверные функции проверять `deno check` и вызовом через `net.http_post`.
- **Выкладка функций.** `deploy_edge_function` с полным текстом файла. У `morning` и `devices` `verify_jwt=false` (свой ключ `x-health-key`), у `coach-ai` `verify_jwt=true`.
- **Коммиты.** Понятное сообщение на английском. После пуша скопировать файлы в `/mnt/project-files/fitbit-app/health-lab/web/`.
- **План.** Текущий план и что сделано — в `/mnt/project-files/fitbit-app/health-lab/notes/plan-2026-10.md`. Новые просьбы владельца добавлять туда этапом с датой и отмечать сделанное.
- **Отчёт владельцу.** Коротко: что сделано, что проверено, что нужно от него. Без внутренних терминов.

- Сменить ключ администратора (`admin_key`), потому что он побывал в ссылках.
- Проверить, что у проекта включены резервные копии.
- Двухфакторный вход (код из приложения-аутентификатора) требует экрана в приложении: сделать по просьбе владельца.
