# Health Lab

Личное веб-приложение (PWA) для данных Fitbit Air из Google Health: готовность, сон, нагрузка и все показатели по дням.
Стиль Apple Health, светлая и тёмная тема, на iPhone ставится на экран «Домой» как приложение.

## Как устроено

- **Next.js 16** (App Router), все экраны клиентские, графики на собственном SVG.
- **Supabase** `yfdaldpzbfyzoancmywn`: сбор данных из Google Health, дневные итоги, нагрузка и готовность считаются в БД
  (код сбора лежит отдельно, в папке проекта `fitbit-app/health-lab/supabase`).
- **Вход** по ссылке на почту (Supabase Auth). Данные отдают только две функции `public.hl_summary(days)` и `public.hl_day(d)`,
  и они отвечают лишь владельцу: почта из `health.sync_state['owner_email']`. Сама схема `health` наружу закрыта.
  Миграция: `supabase/migrations/0007_app_api.sql`.
- В браузере только публичные значения: адрес проекта и publishable-ключ. Секретов в коде и в Vercel нет.

## Экраны

| Путь | Что показывает |
|---|---|
| `/` | Готовность, вывод дня, сон, HRV, пульс покоя, шаги, зоны, температура, SpO₂, дыхание, нагрузка |
| `/sleep?d=` | Гипнограмма, пульс во сне, стадии против нормы, тренды и режим сна |
| `/load` | TRIMP с 7/28-дневными средними, ACWR с безопасной зоной, готовность по дням, время в пульсовых зонах |
| `/data?m=` | Тренд любого показателя за неделю…год, таблица по дням |
| `/day?d=` | Пульс по минутам, шаги по часам, тренировки |
| `/coach` | Цель и рекомендация на день; ИИ-тренер появится на этапе 3 |

## Запуск

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
```

Деплой: Vercel, импорт этого репозитория, настройки по умолчанию. Переменные окружения не нужны
(можно переопределить `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_KEY`).
После первого деплоя адрес сайта добавляется в Supabase → Authentication → URL Configuration (Site URL и Redirect URLs).
